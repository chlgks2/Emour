## 1. Google Cloud — OAuth 2.0 (소셜 로그인)

### 1.1 개요

구글 계정으로 로그인하는 기능에 사용한다. 프론트엔드가 구글로부터 **ID 토큰**을 받아 백엔드에 전달하고, 백엔드는 그 토큰의 `aud`(대상) 필드가 우리 Client ID와 일치하는지 검증한다.

### 1.2 설정 값

| 항목 | 값 |
| --- | --- |
| Client ID | `1029043609489-hgtj3l62pd03jg1t87aeoh7j0g1c2faa.apps.googleusercontent.com` |
| Client Secret | **불필요** (ID 토큰 검증 방식이라 서버가 시크릿을 쓰지 않음) |
| 인증 방식 | Google Identity Services (ID Token) |

### 1.3 주입 경로

| 대상 | 변수명 | 위치 | 주입 시점 |
| --- | --- | --- | --- |
| 백엔드 | GOOGLE_CLIENT_ID | /opt/emour/{prod,dev}/env/api.env | 런타임 |
| 프론트엔드 | VITE_GOOGLE_CLIENT_ID | GitLab CI/CD Variables (Masked) |  |
| → --build-arg | **빌드 타임** |  |  |

프론트엔드 값은 Vite가 빌드 시점에 번들에 박아 넣으므로, 값이 바뀌면 반드시 이미지를 재빌드해야 한다.

### 1.4 발급 절차

1. Google Cloud Console → 프로젝트 생성
2. **API 및 서비스 → OAuth 동의 화면** 구성 (외부 / 테스트 또는 게시)
3. **사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
4. 애플리케이션 유형: **웹 애플리케이션**
5. **승인된 자바스크립트 원본**에 아래 등록
    
    ```
    <https://i15b208.p.ssafy.io>
    <https://i15b208.p.ssafy.io:8080>
    <http://localhost:5173>
    ```
    
6. 생성된 Client ID를 `api.env`와 GitLab CI Variable에 각각 설정

### 1.5 주의사항

- Client ID 자체는 비밀값이 아니다. 프론트엔드 번들에 노출되는 것이 정상이다. 다만 관리 일관성을 위해 환경변수로 다룬다.
- 승인된 자바스크립트 원본에 등록되지 않은 도메인/포트에서 접속하면 로그인 팝업이 `origin_mismatch` 오류를 낸다. **dev 포트(8080)도 반드시 별도 등록**해야 한다.

## 2. Gmail SMTP — 이메일 인증 발송

### 2.1 개요

회원가입 시 이메일 인증 코드를 발송한다. Spring Boot의 `spring-boot-starter-mail`을 사용한다.

### 2.2 설정 값

| 항목 | 값 |
| --- | --- |
| 호스트 | `smtp.gmail.com` (기본값) |
| 포트 | `587` (STARTTLS) |
| 계정 | `devemail208@gmail.com` |
| 비밀번호 | `<발급값>` — **앱 비밀번호** |
| 발신 주소 | 계정과 동일 |

### 2.3 주입 경로

`/opt/emour/{prod,dev}/env/api.env`

| 변수 | 값 |
| --- | --- |
| EMAIL_MODE | smtp |
| MAIL_USERNAME | devemail208@gmail.com |
| MAIL_PASSWORD | <발급값> |
| MAIL_HOST / MAIL_PORT | 미지정 (기본값 사용) |

`EMAIL_MODE`는 `smtp` / `console` 두 값을 가진다. `console`이면 실제 발송 대신 로그에 인증 코드를 출력하므로 **로컬 개발이나 발송 장애 시 우회 수단**으로 쓸 수 있다. 기본값은 `console`이다.

### 2.4 앱 비밀번호 발급 절차

일반 계정 비밀번호로는 SMTP 인증이 되지 않는다. 별도의 16자리 앱 비밀번호가 필요하다.

1. 구글 계정 → **보안** → **2단계 인증** 활성화 (선행 필수)
2. **앱 비밀번호** 메뉴 진입
3. 앱 이름 입력 후 생성 → 공백 포함 16자리 문자열 발급
4. **공백을 제거**한 상태로 `MAIL_PASSWORD`에 설정

### 2.5 주의사항

- 무료 Gmail 계정은 **하루 약 500통** 발송 제한이 있다. 시연 중 대량 가입 테스트 시 도달할 수 있다.
- 앱 비밀번호는 재확인이 불가능하다. 분실 시 삭제 후 재발급한다.
- 이 값이 유출되면 해당 계정으로 임의 메일을 보낼 수 있다. 노출 시 즉시 폐기한다.

    - 최초 기동이 수 분 소요된다 (`start_period: 120s` 설정 이유)

    - 컨테이너를 재생성하면 캐시가 사라져 다시 받는다.
- `uvicorn --workers 1` 고정. 워커가 늘면 모델이 프로세스별로 중복 적재되어 2500m 메모리 상한을 넘긴다.

## 4. SSAFY GMS Gateway — 답장 추천 LLM

### 4.1 개요

답장 문구 추천 기능이 사용하는 LLM 호출 경로. SSAFY가 제공하는 게이트웨이를 통해 OpenAI 모델을 호출한다. OpenAI Chat Completions와 **호환되는 인터페이스**이므로 `openai` 파이썬 SDK를 `base_url`만 바꿔 그대로 사용한다.

### 4.2 설정 값

| 항목 | 값 |
| --- | --- |
| Base URL | https://gms.ssafy.io/gmsapi/api.openai.com/v1 |
| 모델 | gpt-4.1 / gpt-4.1-mini(저토큰용) |
| Temperature | 0.7 |
| Timeout | 8초 |
| API Key | <발급값> |

### 4.3 주입 경로

`/opt/emour/{prod,dev}/env/ai.env`

| 변수 | 값 |
| --- | --- |
| SUGGEST_ENABLED | true |
| GMS_API_KEY | <발급값> |
| GMS_BASE_URL | https://gms.ssafy.io/gmsapi/api.openai.com/v1 |
| SUGGEST_MODEL | gpt-4.1 |
| SUGGEST_TEMPERATURE | 0.7 |
| SUGGEST_TIMEOUT_SEC | 8 |
| INTERNAL_API_KEY | 주석 처리 (내부 호출 인증, 선택) |

프롬프트 버전은 환경변수가 아니라 코드 상수다
: `AI/app/prompts_suggest.py` → `DEFAULT_PROMPT_VERSION = "v5"`

### 4.4 킬 스위치

`SUGGEST_ENABLED=false` 로 바꾸고 ai 컨테이너만 재기동하면 **재배포 없이** 답장 추천 기능을 차단할 수 있다. 크레딧 소진, 게이트웨이 장애, 응답 품질 문제 발생 시 즉시 사용한다.

```bash
sudo sed -i 's/^SUGGEST_ENABLED=.*/SUGGEST_ENABLED=false/' /opt/emour/prod/env/ai.env
cd /opt/emour/prod && docker compose up -d ai
```

### 4.5 주의사항

- **크레딧이 SSAFY 계정 단위로 제한**된다. 실험·평가 반복 시 소진에 유의한다.
- `SUGGEST_TIMEOUT_SEC=8` 초과 시 재시도 후 `llm_failure`를 반환한다. Nginx `/ai/` 의 `proxy_read_timeout 300s`와는 별개다.
- 게이트웨이 URL이 반드시 **OpenAI 호환 Chat Completions 경로**여야 한다. 다른 경로를 넣으면 SDK가 404를 받는다.
- 사용자의 실제 대화 내용이 외부 LLM으로 전송된다. 개인정보 처리 관점의 고지·동의가 필요한 영역이다.

## 6. Let's Encrypt — HTTPS 인증서

### 6.1 개요

무료 TLS 인증서 발급 기관. Certbot 2.9.0으로 발급·관리한다.

### 6.2 인증서 현황

| 인증서명 | 도메인 | 키 타입 | 만료일 | 용도 |
| --- | --- | --- | --- | --- |
| i15b208.p.ssafy.io | i15b208.p.ssafy.io | ECDSA | **2026-10-28** | prod(443) + dev(8080) 공용 |
| p.ssafy.io | *.p.ssafy.io | ECDSA | 2026-09-21 | SSAFY 발급 와일드카드 |

경로: `/etc/letsencrypt/live/<인증서명>/{fullchain.pem, privkey.pem}`

### 6.3 발급 / 확인

```bash
sudo certbot --nginx -d i15b208.p.ssafy.io   # 최초 발급
sudo certbot certificates                     # 현황 확인
sudo certbot renew --dry-run                  # 갱신 리허설(실제 발급 없음)
```

### 6.4 주의사항 — 자동 갱신 실패 상태

`certbot renew --dry-run` 결과 **두 인증서 모두 갱신 실패**한다.

| 인증서 | 실패 원인 |
| --- | --- |
| `i15b208.p.ssafy.io` | HTTP-01 챌린지가 80 포트로 들어와야 하나 UFW·Nginx 양쪽에서 미개방 → 타임아웃 |
| `p.ssafy.io` | manual 플러그인이 `--manual-auth-hook` 없이 비대화식 실행 불가. SSAFY 발급분이라 팀 소관 아님 |

```bash
sudo systemctl restart gitlab-runner
```

등록 후 GitLab UI에서 태그를 `emour-ec2`로 설정해야 `.gitlab-ci.yml`의 `tags: [emour-ec2]` 와 매칭된다.

### 7.5 주의사항

- Runner 등록 토큰은 재확인이 어렵다. 발급 시 안전한 곳에 보관한다.
- `gitlab-runner` 계정이 `/opt/emour/scripts/deploy.sh` 를 실행하고 `/opt/emour/*/env/` 를 읽어야 하므로 `deploy` 그룹 권한 확인이 필요하다.
    
    ```bash
    sudo usermod -aG deploy gitlab-runner
    ```

## 8. 비밀값 관리 원칙

| 원칙 | 내용 |
| --- | --- |
| Git 커밋 금지 | `.env` 계열은 절대 커밋하지 않는다. 확인: `git ls-files |
| 파일 권한 | env 파일은 `640` (`ubuntu:deploy`). 그룹 외 사용자는 읽을 수 없다 |
| 로그·채팅 노출 금지 | 값 확인 시 `grep -oE '^[A-Z_0-9]+'` 로 **키 이름만** 출력한다 |
| CI Variables 최소화 | 빌드 타임에 반드시 필요한 값만 등록한다 |
| 마스킹 | GitLab Variable은 Masked 속성을 켜서 job 로그에 노출되지 않게 한다 |
| 로테이션 | 유출 의심 시 즉시 재발급. `JWT_SECRET` 교체 시 전 사용자 재로그인이 발생함을 사전 공지한다 |

키 생성 명령:

```bash
openssl rand -base64 32   # CHAT_ENCRYPTION_KEY (반드시 32바이트)
openssl rand -base64 48   # JWT_SECRET
openssl rand -base64 24   # DB / Redis 비밀번호
```
